## 2. 基线 A vs B 决策清单（拿到任务包后 1 天内定）

| 判据 | 倾向 A | 倾向 B |
|---|---|---|
| 解码函数签名能拿到超图 / 邻接 | ✔ D1（关键性 FM 细化）可做，确定性杠杆最大 | |
| 解码只给嵌入 + 面积 | | ✔ A 的解码只剩 D0/D2/D5，优势缩水 |
| A 的解码输出后**没有**官方修复（#17） | 解码必须自带可行性保证 → gate 要做硬平衡检查；但也意味着解码完全掌控最终切分，杠杆更大 | 若解码不带修复而 LLM 写不稳可行性 → 倾向 B |
| 初始算法质量（基线 9 次运行的 cut / 平衡偏差 / 修复翻动量） | 基线 A 更弱（k-means 平衡修复翻动大）→ 改善空间大 | 基线 B 更弱 → 同理 |
| 本地试跑：让 Flash 分别改 A 的两个函数 / B 的一个函数各 10 次，gate 一次通过率 | A ≥ 70% | B 明显更高 |
| 单次训练 + 解码耗时 | 聚类在十万节点上慢（k-means 快但 FM 慢） | 端到端通常更快 |
| 种子方差（基线 3 种子 Hamming 两两） | A 方差大 → 有解码可稳 | B 方差小 → 更稳 |
| 损失与下游指标的"直接性" | 对比损失间接 | 题面明说 B"与优化目标直接相关、更自由" |

默认倾向：**若 D1 可做则 A，否则 B**。无论选哪个，harness 两套配置都保留并测试，提交时只固定一套。
