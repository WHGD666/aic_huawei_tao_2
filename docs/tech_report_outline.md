# 技术报告骨架（对照原文附录六节）

> 素材来源：`workspace/tools/report.py`（运行目录 → 预算 / 效率曲线 / 候选表 / 相关面板 / 基线对比 / 血统）+ `docs/rehearsal_report_R30_prob.md`（彩排过程数据）+ `docs/hypothesis_library.md`（机制与公式）+ `docs/open_questions.md`（口子与答疑结论）。报告本身**不计分**，但它是评委核验 harness 行为、理解最终损失函数的主要窗口，必须写清楚机制、实验与局限。

## 一、算法概述
- 网表切分问题：双层 3D IC，跨层网经 HBT；切分决定割网、关键路径跨层与层间面积分布，进而影响后续固定流程（布局→PDN→HBT 分配→时序优化→STA）的时序结果。
- 已有主流方法：min-cut / 面积均衡启发式；TP-GNN 类表示学习 + 聚类；端到端概率预测 + 可微割网/平衡。
- 所选基线：**概率预测（只演化损失）** 或 **表示学习（损失 + 解码）**——写出选择依据（`docs/open_questions.md` §2 决策清单的实测结论）。
- harness 主要思路：预算感知的"免费预筛 + 昂贵验证"；函数级边界与可微门禁；代理指标只做筛选与方向提示；稳健选择（mean−σ−κ·seed_σ，全正优先）。
- 相对初始算法的结果：训练集三算例的 WNS/TNS 改善比例表（真实运行后填）。

## 二、实现方案
- harness 动机与工作流程 / 伪代码（提交点：`harness/loop.py`）。
- 提示词组织：system 硬规则、knowledge 机制块、阶段菜单、画像与历史（算例匿名）、代理相关性面板、父代 patch 与代码片段（SEARCH 预检）。
- 工具调用：LLM 一次产出 k 个候选；本地 gate / 冒烟 / 代理运行 / 去重 / 选择。
- 反馈分析：规则摘要（按算例按种子）+ Spearman 代理↔真实 + LLM ≤120 词解读。
- **最终损失函数逐项解释**：每一项的动机、公式、对梯度的影响（如关键对拉普拉斯在饱和边缘处的梯度、扇出阻尼对时钟网的处理、平衡 hinge 的死区宽度选择），以及它与物理收益的对应关系。
- 若选表示学习基线：解码方法（平衡约束下的细化）及其与学习目标的配合。

## 三、实验与创新点
- 训练与公开验证算例的完整指标对比表（基线 vs 最终算法，每算例每种子）。
- 演化效率：第 k 次评估后的最优分数曲线（report.py §2）；API 费用与 token（report.py §1）。
- 消融：`config/harness.yaml: ablation` 每项开关的对比表（无代理层 / 无画像 / 无 precheck / 无历史分析 / 无 LLM 分析 等），给出"代理筛选贡献了多少次评估节省""门禁拦截率"。
- 关键案例分析：选 2–3 个祖孙候选，展示 LLM 的诊断与机制演化（彩排里的 c021→c035→c067 链条是一个模板，真实运行后重写）。
- 创新点摘要：函数级 AST 门禁、可微冒烟、切分指纹去重、代理↔真实秩相关回灌、稳健选择规则、预算分段与续跑。

## 四、问题与思考
- 未改善或失败算例：哪个算例的什么机制失效、为什么（关键性迁移失败、修复程序破坏、种子方差）。
- 跨算例适应：训练可见 3 个、计分 7 个；过拟合迹象与对策。
- 搜索稳定性：相同系数不同种子的差异；重复切分说明目标函数在该粒度不敏感。
- 方法局限：2D 关键性 ≠ 3D 瓶颈；损失与最终 STA 指标之间隔着固定流程；代理指标在真实链路上的有效性依赖官方流程结构。
