## 2. 演化轨迹（LLM 实际做了什么）

血统主干与替身分数的走向：

```
c004  +0.065   关键对拉普拉斯（星型展开）——第一次正分
 └ c021/c027/c029  诊断"双重计权/梯度被 star 形式稀释"，逐步改写
    └ c035  +0.165   重写后用"边级 w=0.5·c_i·c_j·(p_i−p_j)²"——三算例 +0.159/−0.013/+0.019（过拟合 C1）
       └ c037/c056/c065  叠加扇出阻尼割权重 1/log(1+k)；系数扫描
          └ c067/c068  locality 系数 1.0→0.7，收紧到三算例全非负（+0.074/+0.029/+0.015）
             └ c079/c080 去掉 crit² 软门控，微调
c005  −0.867   把割项整体换成 star 展开（信息量最大的反例：割项本身不能动）
c008  −0.719   宏平衡 hinge（单探针就负 → 宏在替身里不是瓶颈）
c039  −0.952   平衡项换成平滑 hinge（单探针就负 → repair 被绕过）
```

观察：

1. **LLM 自己完成了"机制发现 → 因果诊断 → 系数扫描 → 收窄到稳健点"的闭环**。c021/c027/c029 的诊断（"父代 l_loc 对 crit 双重计权"、"star 展开把差异平方平均掉"）与最终胜出的机制（**边级关键对拉普拉斯 + 扇出阻尼割权重**）与假设库 §4.1 的 B5/B9 预测方向一致——这是题面"解题思路"点名方向（把时序关键性引入连接代价）的一个具体可微形式。
2. **探针阶段确实筛掉了错方向**：把割项换 star 形式（c005）、宏 hinge（c008）、平滑 hinge（c039）都是单探针即负，后续没有再浪费评估。
3. **代理↔真实秩相关在运行中被学到并回灌**：以 30 个评估候选计，`crit_cross` ρ=−0.65（关键对跨层比例越低分越高）、`wcut` ρ=−0.46、`repair_flips` ρ=+0.47、`cut` ρ=−0.15。选父代/选提交对象时提示词里带这张表，LLM 在 c023 明确引用了"crit_cross 是最强负相关指标"——**代理层的信息价值被证明成立**（代价是替身里的相关结构是我们设计的，真实链路待核实）。

## 3. 暴露并已修复的问题

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | `git apply` 在"work 目录位于某个 git 仓库内"时**静默返回 0 但什么都不改** | structural 阶段所有候选的 SEARCH 全部失配（父代改动没进工作副本），fatal | 换成纯 Python unified-diff 应用（逐 hunk 校验上下文，原子写；不依赖 git，也不受"work 在仓库子目录里"影响），失败才回退复制父代 work；补往返一致性测试 |
| 2 | `tiny_torch` 缺 `Tensor.std`、`torch.zeros(n, dtype=p.dtype)` 等常用写法 | 合法候选被误判 gate 失败（c003）；这是替身后端的 bug，不是候选的错 | 补齐 60+ 算子与 dtype 归一化（`_np_dtype`），`zeros/ones/randn/rand/arange/full` 接受任意 dtype |
| 3 | final 阶段连续 10 个候选的切分与已评估候选**逐字节相同**（系数微调低于离散化阈值） | 白烧 10 轮 LLM 费（约 0.02 元；真实评估不烧次） | ① 连续 duplicate 计数，达上限即停（`budget.max_consecutive_duplicates`）② final 提示词明确"duplicate = 该粒度不敏感，改为换形式/加删整项/收紧死区"③ 历史摘要里 duplicate 行直接写"不要重复该粒度" |
| 4 | 分段续跑时停在 `proposed` 的候选悬空 | 血统里出现无结论节点 | 启动时把 `proposed` 标为 `discarded`，原因"run interrupted" |
| 5 | `--ref` 为空时 argparse 报错 | 首轮基线评估失败 | 命令模板里空 `{ref}` 自动去掉 |
| 6 | 评估子进程 cwd 不对 | 相对路径找不到模块 | `CommandEvaluator` 增加 `cwd`（默认 workspace） |

## 5. 结论与下一步

1. **harness 的六步循环、预算刹车、代理筛选、去重、稳健选择、记账在 30 次预算下全部按设计工作**，总费用 0.31 元，远低于 15 元上限——真实运行时评估次数才是约束。
2. **最大的待核实假设仍是"本地跑切分不计入 30 次评估"**（open_questions #1）。若不计次，本题 harness 相对"直接提交"的增益就是本报告第 2 节展示的那样：探针淘汰错方向 + 代理相关性回灌 + 指纹去重省次。

4. 替身数据揭示的机制方向（关键对边级拉普拉斯 + 扇出阻尼割权重）已写进 knowledge 块与探针菜单的优先序，但**在真实物理反馈之前不作为结论**。
